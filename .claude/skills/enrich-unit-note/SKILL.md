# 단원노트 교육자료화 + 그림 첨부

사용자는 **보기 좋아야 공부가 되는** 사람이다. 목표는 시험 대비 요점 노트를, 처음 보는 사람도 그림을 보며 따라갈 수 있는 교육자료로 바꾸는 것이다. 기준 예시는 `30_공유압/공유압_기초.md` — 막히면 이 파일을 열어 구조와 톤을 그대로 따른다.

## 작업 범위와 진행 방식

사용자는 이 볼트 작업의 **판단 권한을 전부 위임했다.** 지켜야 할 선은 단 하나, **기존 내용을 누락시키지 않는 것**이다. 구조 변경, 제목·번호 정리, 링크 추가, 노트 분할·병합, 그림 선택은 묻지 않고 스스로 판단해 처리한다. 실수는 git 히스토리로 되돌릴 수 있다는 것이 사용자의 전제다 — 그래서 히스토리를 지우는 `git push --force`, `git reset --hard` 후 푸시, `--no-verify`는 하지 않는다. 그것만은 되돌릴 수 없다.

이 스킬의 한 번 실행은 **노트 보강 → 그림 → 확인 → 커밋 → 푸시**까지다. 노트 하나를 마칠 때마다 따로 묻지 않고 커밋·푸시한다.

### 내용 누락 검사 (구조를 크게 바꿀 때마다)

문서를 재구성하면 커밋 전에 스크립트로 확인한다: 원본(`git show HEAD:<파일>`)의 비어 있지 않은 줄에서 Markdown 기호(`#`, `-`, `*`, `>`, 표 구분선)를 걷어낸 핵심 문장이 새 파일에 모두 남아 있는지 본다. 빠진 줄이 있으면 되살린 뒤에 커밋한다. 형식만 바뀐 줄(제목 ↔ 굵은 글씨 등)은 정상이다.

### 여러 노트를 맡았을 때 (예: "공유압 1~10 진행")

1. **계획부터 세운다.** 대상 노트를 폴더 README 순서(없으면 파일 이름 순)로 번호를 붙여 작업 목록(update_plan)에 한 줄씩 올린다. 이미 보강된 노트(`## 학습 목표` 절이 있는 노트)는 건너뛰고 목록에 "이미 완료"로 표시한다.
2. **1번부터 순서대로, 끊지 않고 끝까지 간다.** 한 노트가 끝나면 커밋·푸시하고 바로 다음 번호로 넘어간다. 중간에 "다음 것도 할까요?"라고 묻거나 턴을 끝내지 않는다 — 사용자가 원하는 것은 맡겨 두면 끝까지 되어 있는 것이다. 진행 상황은 작업 목록과 짧은 한 줄 메모로만 알린다.
3. **노트 단위로 커밋한다.** 노트 하나 = 커밋 하나 (노트 + 그 노트의 그림 + `.commons_credits.json`). 중간에 멈추더라도 끝난 노트는 이미 원격에 올라가 있게 하려는 것이다.
4. **막혀도 전체를 멈추지 않는다.** 위키미디어 429가 길어지면 다운로드를 백그라운드로 돌리고 본문을 먼저 쓴다. 그래도 맞는 그림을 못 구하면 직접 그리거나 그 절은 그림 없이 두고, 마지막 보고에 "그림 보류" 목록으로 남긴다.
5. **멈추는 경우는 푸시가 거부될 때뿐이다**(충돌·인증). 원격에 새 커밋이 있어서 거부되면 `git pull --rebase` 후 다시 푸시하고, 그래도 안 되면 그 지점에서 멈추고 보고한다. 내용을 지워야만 할 것 같은 상황은 지우지 말고 옮기거나 합쳐서 해결한다.
6. 모두 끝나면 노트별 결과(넣은 그림 수, 직접 그린 그림, 보류 항목, 커밋 해시)를 표 하나로 보고한다.

## 지켜야 하는 볼트 규칙 (이유 포함)

- **내용은 하나도 빼지 않는다.** 기존 요약·함정·계산 예·기출 포인트·체크리스트는 사용자가 기출을 분석해 쌓은 것이다. 순서를 옮기고 설명을 덧붙이는 것은 되지만 삭제는 안 된다.
- **교재 원문·페이지 캡처 금지** (README 저작권 규칙). 그림은 위키미디어 공용의 CC0 / 퍼블릭 도메인 / CC BY / CC BY-SA만 쓴다. CC BY·BY-SA는 작성자와 라이선스를 밝혀야 합법이므로 출처 표가 반드시 필요하다.
- **이미지는 `attachments/`에 WebP, 1장 1 MB 이하** (README·attachments 규칙). 파일 이름은 `<과목>_<짧은설명>.webp` (예: `공유압_벤투리관.webp`).
- **링크는 상대 경로 표준 Markdown** — GitHub에서도 보이게 하기 위해서다. 폭 지정은 Obsidian 문법 `![설명|폭](../attachments/파일.webp)`. 표 안에서는 `|`를 `\|`로 이스케이프한다.
- frontmatter의 `tags` 첫 항목(`주제/과목/세부주제`)은 그래프 색을 정하므로 건드리지 않는다.

## 노트 구성

순서는 이렇다. 각 단원에 맞게 절 수와 제목은 바꾼다.

1. frontmatter (그대로)
2. `# 제목`, `[!summary] 핵심 요약`, `[!warning] 자주 틀리는 포인트` (그대로 유지)
3. `## 학습 목표` — "이 단원을 마치면 …할 수 있다" 4~6개. 계산·구분·설명처럼 확인 가능한 동사로 쓴다.
4. `## 한눈에 보기` — 개념 사이 관계를 보여주는 Mermaid `flowchart` 하나.
5. `## 1. …` ~ `## N. …` 개념 절. 각 절은 다음 흐름을 따른다:
   - **직관/비유 한두 문장** (일상 예: 압정, 호스 끝 누르기). 공식부터 들이밀지 않는 이유는, 그림과 비유로 먼저 감을 잡아야 공식이 외워지기 때문이다.
   - **그림** (있으면) + 바로 아래 *기울임 캡션*으로 그림에서 무엇을 봐야 하는지 짚는다.
   - **공식** `$$ … $$` 블록.
   - 기존 표·불릿·계산 예를 해당 절로 옮긴다.
   - 필요하면 `> [!tip]`(감 잡기), `> [!question] 시험에서는`(출제 함정) 상자.
6. 기존 정리표가 있으면 관련 절 끝에 `### … 정리표`로 둔다.
7. 비교 절(예: 공압 vs 유압)은 두 사진을 표 한 줄에 나란히 놓으면 차이가 한눈에 보인다.
8. 기존 `## 그림`, `## 기출 포인트`, `## 관련 단원`, `## 체크리스트` 유지.
9. `## 참고` 아래 `### 그림 출처` 표 (스크립트가 만들어 준다). 직접 그린 그림이 있으면 그 사실도 한 줄 적는다.

노트 길이는 원래보다 1.5~2배가 자연스럽다(기초 노트는 168 → 288줄). 분량 채우기용 문장은 넣지 않는다.

## 그림 찾기 → 넣기 절차

### 1. 그림이 필요한 자리 고르기
절마다 "그림이 있으면 이해가 빨라지는가"로 판단한다. 원리도(유압 잭, 벤투리관), 실물 사진(압력계, 실린더, 베어링), 비교도(층류/난류), 애니메이션(보일 법칙)이 효과가 크다. 보통 노트 하나에 5~8장.

### 2. 검색
```powershell
python -I .claude/skills/enrich-unit-note/scripts/commons_search.py "hydraulic jack principle" "venturi tube" "pneumatic cylinder"
```
- **영어 검색어**가 결과가 훨씬 많다. 원리도는 `svg`, `diagram`, `principle`을 붙이면 잘 나온다.
- 위키미디어는 요청 속도 제한(HTTP 429)이 심하다. 검색어 여러 개를 **한 번에** 넘기고, 연달아 여러 번 호출하지 않는다. 스크립트가 알아서 기다렸다 재시도한다.
- 라이선스가 불분명한 결과는 스크립트가 걸러낸다.

### 3. 다운로드 + WebP 변환 + 출처 표
```powershell
python -I .claude/skills/enrich-unit-note/scripts/commons_fetch.py --prefix 공유압 "File:Working principle of a hydraulic jack.svg=파스칼_유압잭" "File:Venturi-tube.svg=벤투리관"
```
- `attachments/<prefix>_<이름>.webp`로 저장하고, 마지막에 `### 그림 출처`에 붙일 Markdown 표를 출력한다.
- 받은 기록은 `attachments/.commons_credits.json`에 쌓여서, 429로 중간에 끊겨도 다시 실행하면 이어 받는다.
- 오래 걸리면(그림 여러 장 + 429) 백그라운드로 돌리고 그동안 본문을 쓴다.

### 4. 받은 그림을 반드시 직접 본다
Read 도구로 각 WebP를 열어 확인한다. 검색 제목과 실제 그림이 다른 경우가 많다 (예: "Venturi tube"가 세로관이 아니라 U자관 액주계였다). **캡션은 실제로 보이는 것에 맞춰 쓴다.** 틀린 그림은 지우고(`rm attachments/파일.webp` 한 개씩) 다른 후보로 바꾼다.

### 5. 맞는 공개 그림이 없으면 직접 그린다
SVG로 그려 `attachments/<과목>_<이름>.svg`에 둔다 (예: `공유압_절대압_게이지압.svg`).
- 흰 배경 `rect`를 깔아 Obsidian 어두운 테마에서도 보이게 한다.
- 색은 과목 팔레트를 쓴다: 자동제어 `#2F5597`, 기계요소설계 `#548235`, 공유압 `#C55A11`, 강조 빨강 `#C00000`.
- 글꼴은 `Malgun Gothic, Apple SD Gothic Neo, sans-serif`.
- 브라우저 창에 띄워 **글자와 막대가 겹치지 않는지** 확인한다 (처음 그린 그림은 거의 항상 한두 군데 겹친다).

## 마무리 확인

- 노트의 모든 `../attachments/…` 링크와 `….md` 링크가 실제 파일을 가리키는지 스크립트로 확인한다.
- 기존 기출 포인트·체크리스트 항목 수가 줄지 않았는지 확인한다.
- Obsidian이 열려 있으면 작업 중에 표 간격을 자동 정렬해 파일이 "바뀌었다"고 나올 수 있다. diff가 공백뿐이면 다시 읽고 덮어써도 된다.
## 커밋과 푸시

노트 하나를 마치면 바로 한다.

```powershell
git add "30_공유압/공유압_기초.md" attachments/공유압_*.webp attachments/공유압_*.svg attachments/.commons_credits.json
```
- **그 노트와 그 노트의 그림만** 스테이징한다. `.obsidian/graph.json`, `workspace.json` 같은 Obsidian 자동 저장 파일은 사용자가 화면을 만지며 생긴 변경이라 넣지 않는다.
- 커밋 메시지는 영어 한 줄 요약 + 넣은 그림 목록, 끝에 시스템이 알려주는 Co-Authored-By 줄. 예: `Enrich 공압_밸브 note with intuition-first sections and 6 Commons images`
- `git push` 후 출력에서 `main -> main`을 확인한다. 거부되면 위 "멈춰야 하는 경우"에 따른다.
