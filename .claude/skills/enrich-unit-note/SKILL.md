# 단원노트 교육자료화 + 그림 첨부

사용자는 **보기 좋아야 공부가 되는** 사람이다. 목표는 시험 대비 요점 노트를, 처음 보는 사람도 그림을 보며 따라갈 수 있는 교육자료로 바꾸는 것이다. 기준 예시는 `30_공유압/공유압_기초.md` — 막히면 이 파일을 열어 구조와 톤을 그대로 따른다.

## 작업 범위와 진행 방식

사용자는 이 볼트 작업의 **판단 권한을 전부 위임했다.** 지켜야 할 선은 단 하나, **기존 내용을 누락시키지 않는 것**이다. 구조 변경, 제목·번호 정리, 링크 추가, 노트 분할·병합, 그림 선택은 묻지 않고 스스로 판단해 처리한다. 실수는 git 히스토리로 되돌릴 수 있다는 것이 사용자의 전제다 — 그래서 히스토리를 지우는 `git push --force`, `git reset --hard` 후 푸시, `--no-verify`는 하지 않는다. 그것만은 되돌릴 수 없다.

이 스킬의 한 번 실행은 **노트 보강 → 그림 → 확인 → 커밋 → 푸시**까지다. 노트 하나를 마칠 때마다 따로 묻지 않고 커밋·푸시한다.

### 내용 누락 검사 (구조를 크게 바꿀 때마다)

문서를 재구성하면 커밋 전에 반드시 돌린다:

```powershell
python -I .claude/skills/enrich-unit-note/scripts/loss_check.py 30_공유압/공유압_기초.md
```

원본(기본값 `HEAD`, 두 번째 인자로 다른 커밋 지정 가능)의 각 줄에서 Markdown 기호를 걷어낸 문장이 새 파일에 남아 있는지 본다. `missing: 0`이면 안전하다. 걸린 줄은 하나씩 판단한다:
- **절 제목만 걸림** (예: `## 개념 정리`가 번호 붙은 절로 바뀜) → 새 구조로 대체된 것이라 괜찮다.
- **본문 문장이 걸림** → 표현을 바꿨더라도 원래 문장을 그대로 되살린다. 실제로 처음 보강 때 보일 법칙 계산 예의 식이 빠진 것을 이 검사로 찾았다.

파이썬 문자열로 수식을 치환할 때는 `\nu`, `\theta` 같은 LaTeX가 줄바꿈·탭으로 바뀌지 않게 raw 문자열(`r"..."`)이나 Edit 도구를 쓴다. 셸 heredoc(`<<'EOF'`)으로 넘긴 파이썬 코드는 `\\`가 `\`로 줄어들 수 있으니, 백슬래시가 들어간 코드(LaTeX·정규식)는 Write 도구로 파일을 만든 뒤 실행한다.

### 긴 문서·여러 절을 보강할 때
절 단위 추가 내용은 `=== NN` 구분자로 나눈 Markdown 파일에 쓰고, 각 절 제목 바로 아래에 끼워 넣는 방식이 안전하다 (기존 본문은 그 아래에 그대로 남는다). 그림 다운로드가 429로 늦어지면 **본문을 먼저 커밋·푸시**하고, 그림은 들어오는 대로 다음 커밋에 싣는다. 출처 표는 매번 다시 만든다:

```powershell
python -I .claude/skills/enrich-unit-note/scripts/credits_section.py 00_Inbox/교재_CH01.md
```
아직 안 받아진 그림 목록도 함께 알려 준다.

### 여러 노트를 맡았을 때 (예: "공유압 1~10 진행")

1. **계획부터 세운다.** 대상 노트를 폴더 README 순서(없으면 파일 이름 순)로 번호를 붙여 작업 목록(update_plan)에 한 줄씩 올린다. 이미 보강된 노트(`## 학습 목표` 절이 있는 노트)는 건너뛰고 목록에 "이미 완료"로 표시한다.
2. **1번부터 순서대로, 끊지 않고 끝까지 간다.** 한 노트가 끝나면 커밋·푸시하고 바로 다음 번호로 넘어간다. 중간에 "다음 것도 할까요?"라고 묻거나 턴을 끝내지 않는다 — 사용자가 원하는 것은 맡겨 두면 끝까지 되어 있는 것이다. 진행 상황은 작업 목록과 짧은 한 줄 메모로만 알린다.
3. **노트 단위로 커밋한다.** 노트 하나 = 커밋 하나 (노트 + 그 노트의 그림 + `.commons_credits.json`). 중간에 멈추더라도 끝난 노트는 이미 원격에 올라가 있게 하려는 것이다.
4. **막혀도 전체를 멈추지 않는다.** 위키미디어 429가 길어지면 다운로드를 백그라운드로 돌리고 본문을 먼저 쓴다. 그래도 맞는 그림을 못 구하면 직접 그리거나 그 절은 그림 없이 두고, 마지막 보고에 "그림 보류" 목록으로 남긴다.
5. **멈추는 경우는 푸시가 거부될 때뿐이다**(충돌·인증). 원격에 새 커밋이 있어서 거부되면 `git pull --rebase` 후 다시 푸시하고, 그래도 안 되면 그 지점에서 멈추고 보고한다. 내용을 지워야만 할 것 같은 상황은 지우지 말고 옮기거나 합쳐서 해결한다.
6. 모두 끝나면 노트별 결과(넣은 그림 수, 직접 그린 그림, 보류 항목, 커밋 해시)를 표 하나로 보고한다.
7. 사용자가 노트 목록과 순서를 직접 주면 그 순서를 따른다.

### 노트 하나당 체크리스트 (일괄 실행 때 매번 이 순서로)

1. 노트를 끝까지 읽고, 기준 예시 `30_공유압/공유압_기초.md`의 구성으로 다시 쓴다 (기존 문장은 하나도 지우지 않는다).
2. 그림 자리를 고르고 → 위키미디어 검색·받기 → 막히면 Openverse(`--no-wikimedia`) → 그래도 없으면 직접 그린 SVG.
3. 받은 그림은 Read로 열어 보고 캡션을 실제 모습에 맞춘다. 직접 그린 SVG는 `render_check.py`로 PNG를 만들어 보고 겹침·잘림·원리 오류를 고친다.
4. `credits_section.py <노트>` → `loss_check.py <노트>`(본문 문장 missing 0) → `link_check.py <노트>`(broken 0).
5. 그 노트와 그 노트의 그림만 `git add` → 커밋 → `git push`. 바로 다음 노트로.

## 지켜야 하는 볼트 규칙 (이유 포함)

- **내용은 하나도 빼지 않는다.** 기존 요약·함정·계산 예·기출 포인트·체크리스트는 사용자가 기출을 분석해 쌓은 것이다. 순서를 옮기고 설명을 덧붙이는 것은 되지만 삭제는 안 된다.
- **교재 원문·페이지 캡처 금지** (README 저작권 규칙). 그림은 위키미디어 공용의 CC0 / 퍼블릭 도메인 / CC BY / CC BY-SA만 쓴다. CC BY·BY-SA는 작성자와 라이선스를 밝혀야 합법이므로 출처 표가 반드시 필요하다.
- **이미지는 `attachments/`에 WebP, 1장 1 MB 이하** (README·attachments 규칙). 파일 이름은 `<과목>_<짧은설명>.webp` (예: `공유압_벤투리관.webp`).
- **링크는 상대 경로 표준 Markdown** — GitHub에서도 보이게 하기 위해서다. 폭 지정은 Obsidian 문법 `![설명|폭](../attachments/파일.webp)`. 표 안에서는 `|`를 `\|`로 이스케이프한다.
- frontmatter의 `tags` 첫 항목(`주제/과목/세부주제`)은 그래프 색을 정하므로 건드리지 않는다.

## 노트 구성

순서는 이렇다. 각 단원에 맞게 절 수와 제목은 바꾼다.

1. frontmatter (그대로)
2. `# 제목`, `[!summary] 핵심 요약`, `[!warning] 자주 틀리는 포인트` (그대로 유지)
3. `## 학습 목표` — "이 단원을 마치면 …할 수 있다" 4~6개. 계산·구분·설명처럼 확인 가능한 동사로 쓴다.
4. `## 한눈에 보기` — 개념 사이 관계를 보여주는 Mermaid `flowchart` 하나.
5. `## 1. …` ~ `## N. …` 개념 절. 각 절은 다음 흐름을 따른다:
   - **직관/비유 한두 문장** (일상 예: 압정, 호스 끝 누르기). 공식부터 들이밀지 않는 이유는, 그림과 비유로 먼저 감을 잡아야 공식이 외워지기 때문이다.
   - **그림** (있으면) + 바로 아래 *기울임 캡션*으로 그림에서 무엇을 봐야 하는지 짚는다.
   - **공식** `$$ … $$` 블록.
   - 기존 표·불릿·계산 예를 해당 절로 옮긴다.
   - 필요하면 `> [!tip]`(감 잡기), `> [!question] 시험에서는`(출제 함정) 상자.
6. 기존 정리표가 있으면 관련 절 끝에 `### … 정리표`로 둔다.
7. 비교 절(예: 공압 vs 유압)은 두 사진을 표 한 줄에 나란히 놓으면 차이가 한눈에 보인다.
8. 기존 `## 그림`, `## 기출 포인트`, `## 관련 단원`, `## 체크리스트` 유지.
9. `## 참고` 아래 `### 그림 출처` 표 (스크립트가 만들어 준다). 직접 그린 그림이 있으면 그 사실도 한 줄 적는다.

노트 길이는 원래보다 1.5~2배가 자연스럽다(기초 노트는 168 → 288줄). 분량 채우기용 문장은 넣지 않는다.

## 그림 찾기 → 넣기 절차

### 1. 그림이 필요한 자리 고르기
절마다 "그림이 있으면 이해가 빨라지는가"로 판단한다. 원리도(유압 잭, 벤투리관), 실물 사진(압력계, 실린더, 베어링), 비교도(층류/난류), 애니메이션(보일 법칙)이 효과가 크다. 보통 노트 하나에 5~8장.

### 그림 출처 우선순위 (하나가 막히면 다음으로)

한 곳만 믿으면 그 서버가 막힐 때 작업 전체가 멈춘다. 아래 순서로 내려가되, 어느 단계든 **출처 페이지에서 라이선스를 확인할 수 있는 그림만** 쓴다.

| 순서 | 출처 | 언제 | 도구 |
| --- | --- | --- | --- |
| 1 | 위키미디어 공용 | 기본. 원리도·SVG가 가장 많다 | `commons_search.py` → `commons_fetch.py` |
| 2 | **Openverse** (위키미디어·Flickr·박물관·NASA 등 통합 검색) | 1에 맞는 그림이 없거나 **429가 계속될 때**. 자체 썸네일 서버를 거쳐서 위키미디어 제한을 피한다 | `openverse_search.py` → `openverse_fetch.py` |
| 2b | 그 밖의 공개 라이선스 페이지 (NASA, 박물관 open access, 미 정부 자료 등. **페이지에서 라이선스를 직접 확인할 수 있을 때만**) | Openverse에도 없을 때 | `web_fetch.py --prefix … --url <이미지 URL> --name … --license "CC0" --author … --page <출처 페이지>` |
| 3 | 직접 그리기 | 1·2 모두 없거나, 있는 그림이 시험 정의와 다를 때 | SVG(아래 5번) 또는 Mermaid·표·코드 블록 |
| 4 | 보류 | 위가 다 안 되면 그림 자리를 설명 상자로 바꾸고 최종 보고에 "그림 보류"로 남긴다 | — |

- 라이선스는 어느 출처든 **CC0 / 퍼블릭 도메인 / CC BY / CC BY-SA** 만. NC(비영리)·ND(변경 금지)는 크기 변환·WebP 변환이 '변경'이라 쓰지 않는다.
- **계정·API 키가 필요한 곳**(Pixabay, Unsplash API 등)은 키를 만들지 않는다. 사용자가 키를 직접 준비해 주면 그때 쓴다.
- 구글 이미지 검색 결과, 블로그·쇼핑몰 사진, 교재·기출문제 이미지는 라이선스를 확인할 수 없으므로 쓰지 않는다. **단, 아래 예외 한 가지는 사용자가 직접 승인했다.**
- **예외 — 제조사 카탈로그 사진 (사용자 승인, 2026-11-24)**: 공개 라이선스 그림이 없어 위키미디어·Openverse로 못 채운 기계요소·센서 부품은, 미스미(MISUMI)·THK·NSK·Fluke 같은 **제조사 제품 페이지의 사진**을 `web_fetch.py --personal-use`로 받아 쓴다. 이 사진은 저작권이 제조사에 있으므로 **이 볼트가 비공개(private) 저장소인 동안, 개인 학습용으로만** 쓴다. 지키는 조건: (1) 저장소를 공개로 바꾸거나 노트·그림을 외부에 게시하지 않는다(바꾸려면 이 사진부터 지운다). (2) 반드시 출처 페이지 URL과 회사 이름을 `### 그림 출처` 표에 남긴다(`--page`, `--author`). (3) 구글 이미지 **검색 결과 화면을 긁지 않는다** — 구글은 사진이 있는 제조사 페이지를 찾는 길잡이로만 쓰고, 사진은 그 제조사 페이지(또는 그 CDN)에서 받는다. (4) 로그인·CAPTCHA·봇 차단이 나오면 우회하지 않고 그 항목은 건너뛴다. (5) 사진이 다루는 부품과 캡션이 맞는지 직접 열어 확인하는 것은 다른 출처와 같다. 공개 라이선스 그림이 있으면 그것을 먼저 쓴다.
- **주의**: 위키미디어가 막혀 있을 때는 Openverse도 위키미디어에 올라간 파일은 못 가져온다(424 응답). 이때는 `openverse_search.py --no-wikimedia ...`로 Flickr·박물관 등 다른 곳의 사진만 찾고, 원리도·그래프는 바로 3번(직접 그리기)으로 간다. 실제로 CH01에서는 원리도 9장을 직접 그렸고, 한국어 시험 용어를 그림 안에 바로 쓸 수 있어 오히려 더 좋았다.
- 두 fetch 스크립트는 같은 `attachments/.commons_credits.json`에 기록하고(저장 직전에 다시 읽어 합치므로 동시에 돌려도 안전), `credits_section.py`가 출처 열까지 포함한 표 하나로 만든다.

### 실전에서 알게 된 것 (그림 찾기 요령)
- **429에는 `Retry-After`가 실려 온다** (120~600초). 같은 IP를 여럿이 쓰면 통째로 막히므로 그 시간만큼 기다리고(`commons_fetch.py --patient`), 연달아 두드리지 않는다. 막힌 파일은 백그라운드 재시도에 맡기고 다른 출처로 간다.
- Openverse의 비(非)위키미디어 결과는 대부분 Flickr 개인 사진이라 **제목이 엉뚱한 경우가 많다.** 한 번에 여러 장을 한 장의 컨택트시트로 이어 붙여 Read로 보면 빨리 거를 수 있다. 태그(`/v1/images/<id>/`의 `tags`)가 내용 확인에 도움이 된다(예: Kirkaldy Testing Museum, brinellhardness).
- 효과를 본 검색어: 부품 이름 + `cutaway`/`engraving`, 박물관 이름, 실제 설치 장면(예: `cylinder head studs`). 소스 필터 `--source`는 smithsonian_*·museumsvictoria·rawpixel 모두 기계요소 사진은 거의 없었다.
- **Library of Congress**(loc.gov)는 스크립트 접근에 Cloudflare 확인 화면(403)을 내므로 이 방법으로는 쓸 수 없다 — 우회하지 않는다.

### 2. 검색
```powershell
python -I .claude/skills/enrich-unit-note/scripts/commons_search.py "hydraulic jack principle" "venturi tube" "pneumatic cylinder"
```
위키미디어에서 안 나오면 같은 검색어로 Openverse를 찾는다:
```powershell
python -I .claude/skills/enrich-unit-note/scripts/openverse_search.py "relay coil contact" "optocoupler"
python -I .claude/skills/enrich-unit-note/scripts/openverse_fetch.py --prefix 자동제어 "<openverse id>=릴레이_원리"
```
- **영어 검색어**가 결과가 훨씬 많다. 원리도는 `svg`, `diagram`, `principle`을 붙이면 잘 나온다.
- 위키미디어는 요청 속도 제한(HTTP 429)이 심하다. 검색어 여러 개를 **한 번에** 넘기고, 연달아 여러 번 호출하지 않는다. 스크립트가 알아서 기다렸다 재시도한다.
- 라이선스가 불분명한 결과는 스크립트가 걸러낸다.

### 3. 다운로드 + WebP 변환 + 출처 표
```powershell
python -I .claude/skills/enrich-unit-note/scripts/commons_fetch.py --prefix 공유압 "File:Working principle of a hydraulic jack.svg=파스칼_유압잭" "File:Venturi-tube.svg=벤투리관"
```
- `attachments/<prefix>_<이름>.webp`로 저장하고, 마지막에 `### 그림 출처`에 붙일 Markdown 표를 출력한다.
- 받은 기록은 `attachments/.commons_credits.json`에 쌓여서, 429로 중간에 끊겨도 다시 실행하면 이어 받는다.
- 오래 걸리면(그림 여러 장 + 429) 백그라운드로 돌리고 그동안 본문을 쓴다.

### 4. 받은 그림을 반드시 직접 본다
Read 도구로 각 WebP를 열어 확인한다. 검색 제목과 실제 그림이 다른 경우가 많다 (예: "Venturi tube"가 세로관이 아니라 U자관 액주계였다). **캡션은 실제로 보이는 것에 맞춰 쓴다.** 틀린 그림은 지우고(`rm attachments/파일.webp` 한 개씩) 다른 후보로 바꾼다.

### 5. 맞는 공개 그림이 없으면 직접 그린다
SVG로 그려 `attachments/<과목>_<이름>.svg`에 둔다 (예: `공유압_절대압_게이지압.svg`).
- 흰 배경 `rect`를 깔아 Obsidian 어두운 테마에서도 보이게 한다.
- 색은 과목 팔레트를 쓴다: 자동제어 `#2F5597`, 기계요소설계 `#548235`, 공유압 `#C55A11`, 강조 빨강 `#C00000`.
- 글꼴은 `Malgun Gothic, Apple SD Gothic Neo, sans-serif`.
- **반드시 렌더링해서 눈으로 본다.** 처음 그린 그림은 거의 항상 글자 겹침·오른쪽 잘림이 있다. 여러 장을 한 번에 헤드리스 Edge로 PNG로 찍어 주는 스크립트가 있다 (브라우저 창이 숨겨져 있어도 된다). 출력 폴더는 스크래치 디렉터리로 준다:
  ```powershell
  python -I .claude/skills/enrich-unit-note/scripts/render_check.py <scratch폴더> attachments/자동제어_근궤적.svg attachments/자동제어_릴레이_원리.svg
  ```
  출력된 `render_0.png …`를 Read로 열어 확인한다.
- **내용도 검증한다.** 겹침만 보지 말고 그림이 물리적으로 맞는지 본다. CH01 릴레이 그림은 처음에 지렛대 양 끝이 모두 내려가게 그려서, a접점(NO)을 위로 옮겨 고쳤다. 그래프는 본문 수치와 맞는 예제 값으로 그린다 (퍼지 25 ℃ → 0.7/0.3, 근궤적 극점 0·−2).
- 출처 표의 "직접 그린 그림" 줄은 `credits_section.py`가 SVG 링크를 찾아 자동으로 만든다.

## 마무리 확인

- 노트의 모든 `../attachments/…` 링크, `….md` 링크, `#제목` 링크가 실제 대상을 가리키는지 확인한다: `python -I .claude/skills/enrich-unit-note/scripts/link_check.py <노트>` → `broken 0`.
- 기존 기출 포인트·체크리스트 항목 수가 줄지 않았는지 확인한다.
- Obsidian이 열려 있으면 작업 중에 표 간격을 자동 정렬해 파일이 "바뀌었다"고 나올 수 있다. diff가 공백뿐이면 다시 읽고 덮어써도 된다.
## 커밋과 푸시

노트 하나를 마치면 바로 한다.

```powershell
git add "30_공유압/공유압_기초.md" attachments/공유압_*.webp attachments/공유압_*.svg attachments/.commons_credits.json
```

- `git push` 후 출력에서 `main -> main`을 확인한다. 거부되면 위 "멈춰야 하는 경우"에 따른다.
